Snackbars report on something that has already happened. They should not
interrupt, and they should never be the only place an important message appears.

There are two ways to use them: render `<Snackbar>` yourself, or call the
imperative `snackbar()` function and mount a single `<SnackbarHost />` near the
root of your app.

## Layouts

`singleLine` and `twoLine` keep the action and close button on the message's
row; `longerAction` moves them to a row of their own, for labels too long to sit
beside the text. In every layout the action and close button stay fully round
when pressed, as in the M3 kit, rather than tightening their corners.

## Imperative API

A snackbar with an action or a close button stays until it is dismissed;
otherwise it disappears after four seconds.
