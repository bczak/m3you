Sliders suit values where the exact number matters less than the relative
position — volume, brightness, opacity. Setting `step` turns the slider discrete
and draws stop indicators along the track.

Without `step`, the slider still moves in steps of 1 counted from `min`, like a
native `<input type="range">`, so the value, the value indicator and the
announced value always agree. With or without `step`, values stay on the native
input's grid: when the steps do not divide the range evenly, the highest value
is the last step below `max` (`2` for `0`–`2.7`). For a fractional range such as
`0`–`1`, pass a fractional `step` such as `0.1`; it also draws a stop indicator
per step, so for a fine, continuous-looking control scale the range to whole
numbers (say `0`–`100`) instead.

Use `mode="centered"` for values that diverge from an origin, or `RangeSlider`
when the user needs to choose a lower and upper bound.

## Interaction

The whole slider is a pointer target: pressing anywhere on the track moves the
handle there and starts a drag. In a `RangeSlider` the press goes to the nearer
handle; when both handles sit on the same value, the first drag direction picks
the one that can move (down for the lower, up for the upper). The keyboard
works through the native range inputs. A press focuses the input it moved, so
the arrow keys pick up from there, but it does not draw the keyboard focus ring.
In a `RangeSlider` that ring goes only on the handle whose input has focus.

The tracks run edge to edge while the handle and stop indicators travel 6px in
from each end, and a horizontal slider follows the writing direction, so its
minimum sits on the right in a right-to-left layout. The inset `icon` (md, lg
and xl only) sits 10px in from the start of the active track. Near the minimum,
where the active track is too short to hold the icon with 10px on both sides,
the icon is hidden rather than clipped.
