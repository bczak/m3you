<task type="auto">
  <name>Task 2: Convert rstest.config.ts to two-project config</name>
  <files>rstest.config.ts</files>
  <action>
Replace the current rstest.config.ts (which uses top-level `extends` and `setupFiles`) with a two-project configuration:

```typescript
import { withRslibConfig } from '@rstest/adapter-rslib';
import { defineConfig } from '@rstest/core';

export default defineConfig({
  projects: [
    {
      name: 'unit',
      extends: withRslibConfig(),
      testEnvironment: 'happy-dom',
      setupFiles: ['./rstest.setup.ts'],
      include: ['tests/**/*.test.{ts,tsx}'],
      exclude: ['tests/a11y/**'],
    },
    {
      name: 'a11y',
      extends: withRslibConfig(),
      testEnvironment: 'jsdom',
      setupFiles: ['./rstest.setup.ts', './rstest.setup.a11y.ts'],
      include: ['tests/a11y/**/*.test.{ts,tsx}'],
    },
  ],
});
```

Key decisions:
- `extends: withRslibConfig()` MUST be inside each project (not at root). Per research: top-level `extends` is not inherited by projects when `projects` array is defined.
- Unit project uses `exclude: ['tests/a11y/**']` to avoid running a11y tests under happy-dom (per research Pitfall 7 — use `exclude` not negation in `include`).
- A11y project includes BOTH `rstest.setup.ts` (for cleanup + animate polyfill) and `rstest.setup.a11y.ts` (for axe matchers).
- `testEnvironment` is NOT set at root — it is per-project.

Run `bun run check` after writing the file to ensure Biome formatting compliance.
