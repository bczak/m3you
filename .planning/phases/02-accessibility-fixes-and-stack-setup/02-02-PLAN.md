**IconButton (src/components/ui/icon-button.tsx):**

Add `aria-pressed` attribute to the `<Button>` element. Place it BEFORE the `{...props}` spread so callers can override if needed (consistent with Phase 1 precedent: aria-label before aria-current).

Change the Button render from:
```tsx
<Button
  variant="text"
  ref={ref}
  className={cn(iconButtonVariants({ ... }))}
  {...props}
>
```
To:
```tsx
<Button
  variant="text"
  ref={ref}
  aria-pressed={selected !== undefined ? selected : undefined}
  className={cn(iconButtonVariants({ ... }))}
  {...props}
>
```

The `selected !== undefined ? selected : undefined` check ensures `aria-pressed` is ONLY emitted when the component is used as a toggle button (selected prop explicitly provided). Non-toggle icon buttons must NOT have `aria-pressed`.

**Badge (src/components/ui/badge.tsx):**

1. Add `ariaLabel` to the BadgeProps type:
```tsx
export type BadgeProps = Omit<React.ComponentProps<'span'>, 'children'> &
  VariantProps<typeof badgeVariants> & {
    count?: number;
    max?: number;
    visible?: boolean;
    /** Accessible label for screen readers. Required for dot badges (no visible count text). */
    ariaLabel?: string;
  };
```

2. Destructure `ariaLabel` in the forwardRef function parameters (alongside className, size, count, max, visible).

3. Add `aria-label` to the `<span>` element, BEFORE `{...props}`:
```tsx
<span
  ref={ref}
  aria-label={ariaLabel ?? (!isSmall ? (getDisplayValue() ?? undefined) : undefined)}
  className={cn(badgeVariants({ size: actualSize, className }))}
  {...props}
>
```

Logic: If `ariaLabel` is provided, use it (for any variant). If not provided AND it's a count badge (!isSmall), use the display value (e.g., "5" or "999+"). If not provided AND it's a dot badge, omit aria-label (undefined) — the consumer must pass ariaLabel for accessible dot badges.

Run `bun run check` after both files to ensure Biome compliance.
Run `bun run build` to verify no type errors.
